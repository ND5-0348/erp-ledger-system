## 2. H0 字段落点（摘要）

完整表见 `docs/旧台账字段落点与兼容说明.md`。要点：

- 四级结构落点：框架项目 `project` → 订单 `sales_order` → 子项目 `sub_project` → 明细 `order_line`（A 修正已落地）。
- 四类财务流水列范围：收票 44–46、入库 47–49、入账 50–53、采购付款 54–61、
  销售合同 68–72、开票 73–77、回款 79–88。
- 历史落点（H2 实施）：`project_manager_history` 保存客户经理历次交接，
  `sales_order_number_history` 保存订单号别名；两者主记录同时保留当前值，
  缺少变更日期时留空、不编造，允许重复任职（甲→乙→甲 不去重）。
- 搜索契约（H4）：任一别名都要命中同一订单，后端用 `EXISTS`/去重 ID 过滤，
  **不得多别名 JOIN 后 SUM**（会放大金额）。

**H0 未完成项**：真实旧表未诊断（用户确认暂不提供样本）。旧表的分隔符集合、
相邻多期列排版、旧表头名称与模板的差异都**未核实**，H1 的规则只对合成样本负责。

## 3. H1 纯解析：能力与反例

模块不连库、不读写文件、不依赖当前时间——同样输入永远同样输出，便于预检阶段重放。

| 能力 | 规则 | 反例（用例） |
| --- | --- | --- |
| 名称序列 | `甲/乙/丙`、全角 `／`、`;`、`；`、换行、`、` 都按旧到新切分，**最后一个是当前值**，保留原值 | `甲/乙/甲` 不去重（两次交接） |
| 订单号别名 | `A/B/C` 是同一订单的改号链，不是三个订单 | 与名称序列同一实现 |
| 日期切分 | 按**完整日期语法**分段，不按分隔符切；支持 Excel 日期值、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年M月D日` | `2026/09/01` = **一个**日期；`2026/09/01/2026/09/15` = 两个；`9/1/9/15` 阻断；`2026-02-30`、`2026/13/01`、`2025/02/29` 阻断；`2026/09/01/下月` 阻断 |
| 金额 | Decimal 解析，千分位逗号（含全角）不是分隔符，**0 是有效值** | `1,234.56` = 一个金额；`300/0` 保留 0 |
| 票据号 | 中间空位保留 | `票1//票3` = **三个**位置，不压缩、不复制 |
| 期次配对 | 日期与金额数量一致才配对 | 两日期配 `100/200` → 两笔；两日期配 `300` → `AMOUNT_SPLIT_REQUIRED`；数量不等 → `PHASE_COUNT_MISMATCH`；票据数不符 → 要求补齐位置 |
| 人工分摊校验 | 分摊之和必须等于原合计 | 不等且无理由 → 阻断；填写修正理由 → 通过但标记为非阻断并记录原值 |
| 负责人历史 | 多行完全相同可归一；现任不同必阻断 | `甲/乙/丙` 与 `甲/乙/丙` 归一；`甲/乙` 与 `甲/丙` → `CURRENT_MANAGER_CONFLICT`；`甲/乙/丙` 与 `乙/丙` → `ORDER_HISTORY_CONFLICT` |
| 订单号历史 | 同上 | 现任号不同 → `ORDER_ALIAS_CONFLICT` |

### 错误码

`AMBIGUOUS_DATE_SEQUENCE`、`PHASE_COUNT_MISMATCH`、`AMOUNT_SPLIT_REQUIRED`、
`CURRENT_MANAGER_CONFLICT`、`ORDER_ALIAS_CONFLICT`、`ORDER_HISTORY_CONFLICT`、
`UNPARSABLE_VALUE`。

每个 `Issue` 带 `sheet`、`row`、`columns`、`code`、`message`、`blocking`，
前端按 code 判断流程，不解析中文。

### 数据结构

```text
ParsedCell = {raw_value, tokens, issues}
Issue      = {sheet, row, columns, code, message, blocking}
Phase      = {source_columns, source_position, date, amount, document_no}
```
