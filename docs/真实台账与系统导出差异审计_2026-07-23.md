# 真实台账与系统导出差异审计

- 审计日期：2026-07-23
- 真实台账：`C:\Users\asus\Desktop\2026市场部台账真实数据.xlsx`
- 系统导出：`C:\Users\asus\Downloads\市场部业务台账 (1).xlsx`
- 对账主键：项目编号 + 订单号 + 货物名称 + 规格型号 + 单位 + 数量 + 采购厂商
- 金额容差：0.01 元

## 一、结论

系统导出与真实台账存在 4 类差异：

1. **系统计算口径错误**：应收款、税金、毛利润、毛利率与真实台账公式不一致，已影响首页仪表盘和台账汇总。
2. **数据模型粒度错误**：项目名称存放在项目级，但真实数据中同一项目、甚至同一订单可包含多个项目名称，导入时会被后续明细覆盖；客户单位、客户经理、用户的粒度也需继续按真实数据复核。
3. **生产数据已被测试操作改变**：3 条真实订单已被软删除，另有 1 笔 100 元回款只存在于系统中。
4. **原 Excel 自身存在公式缺陷**：回款占比、毛利率有除零错误，合计行部分公式范围错误，空白区公式扩展到 10815 行。

订单金额、采购金额、交付金额、付款金额、开票金额在排除已删除订单后总体可以对上，差异主要是分币级舍入，不是大范围字段错位。

## 三、P0：必须优先修复

### 1. 项目级字段覆盖了订单级字段

当前数据库以 `project_code` 唯一保存项目名称；导入和编辑任意一条明细时都会更新同一个 `project` 记录。因此，同一项目编号下不同订单或同一订单中的不同业务子项会被最后导入或最后编辑的一条覆盖。

真实台账已经证明这些字段并非项目级唯一：

- 7 个项目编号包含多个项目名称；
- 6 个项目编号包含多个客户单位；
- 1 个项目编号包含多个客户经理；
- 2 个项目编号包含多个“用户”值；
- 例如 `AH24000060-01` 对应 14 个不同客户单位；
- 例如 `AH25000066-01` 对应 29 个不同项目名称。

在 380 条可唯一一一匹配的明细中，至少发现：

- 客户单位名称不一致 199 条；
- 客户经理不一致 149 条；
- 项目名称不一致 77 条；
- 用户不一致 3 条。

影响：

- 台账、销售、采购页面显示错误；
- 查询筛选结果错误；
- 编辑一条订单可能改变同项目下其他订单；
- 操作日志虽然记录了修改，却无法表达被连带覆盖的其他订单；
- 按客户、经理、用户、项目名称统计都会失真。

修改建议：

1. `project` 表仅保留真正项目级且唯一的字段，例如项目编号。
2. 将项目名称放到 `order_line`，以 Excel 业务行/货物明细为粒度保存；查询和导出优先读取明细项目名称。不能只迁移到 `sales_order`，因为 `AH25000075-01` 已证明同一订单号也存在多个项目名称。
3. 导入时禁止 `ON DUPLICATE KEY UPDATE project` 覆盖订单级字段。
4. 编辑订单明细时只更新当前订单上下文，不更新整个项目。
5. 增加回归测试：同一项目、同一订单下两条明细使用不同项目名称和采购商，编辑其中一条后另一条必须不变，订单汇总仍只显示一行。

### 2. 应收款公式使用了错误基数

真实台账公式：

```text
应收款 = 交付价值 - 回款合计
```

系统当前公式：

```text
应收款 = 销售订单金额 - 回款合计
```

共同的 88 个订单中：

- 真实台账应收款合计：8,481,730.04 元；
- 系统导出应收款合计：10,750,468.12 元；
- 系统多计：2,268,738.08 元。

例如 `AH24000082-01 / XSDD2026021000233` 尚未交付，真实台账应收款为 0；系统以订单金额减 100 元回款，导出应收款 157,275.74 元。

影响：

- 首页“应收账款”卡片明显偏高；
- 项目/订单关闭状态错误；
- 回款预警和经营分析失真；
- 未交付订单被提前计入应收。

修改建议：

1. 统一修改数据库视图、台账导出 SQL、销售列表和首页仪表盘：

   ```text
   应收款 = 交付价值 - 多期回款合计
   ```

2. 交付价值为空时按 0 处理。
3. 处理分币误差：绝对值小于 0.01 元时归零。
4. 关闭状态应基于“已交付且应收款结清”，不能只判断订单金额减回款。

### 3. 税金、毛利润、毛利率口径错误

真实台账口径：

```text
不含税毛利润 = 不含税收入 - 不含税成本
税金 = 按统计类别/团队对应税率系数 × 不含税毛利润
毛利润 = 订单价值 - 采购金额 - 税金 + 退税
毛利率 = 毛利润 ÷ 订单价值
```

系统当前口径：

```text
税金 = 销项税额 - 进项税额
毛利润 = 订单价值 - 采购金额
毛利率 = 不含税毛利润 ÷ 不含税收入
```

共同的 88 个订单中：

- 真实台账毛利润合计：844,186.79 元；
- 系统导出毛利润合计：953,957.45 元；
- 系统多计：109,770.66 元；
- 86 个共同订单的毛利润不一致。

影响：

- 首页毛利润约显示 95.4 万，而真实台账总毛利润约 84.71 万；
- 毛利润、毛利率排名和部门绩效错误；
- 税金字段不能与真实经营台账核对。

修改建议：

1. 由业务负责人确认并固化真实台账中的税金分类规则。
2. 在数据库视图或统一计算服务中只维护一份公式；导出、列表、详情和仪表盘全部引用同一结果。
3. 增加 `tax_amount`、`tax_refund`、`gross_profit`、`gross_profit_rate` 的单元测试。
4. 必测边界：订单价值为 0、负毛利、零成本、退税、缅甸团队、装卸/工程/服务/检测/仓储/运输/逆向物流等分类。

## 四、P1：重要修复

### 4. 旧台账导入后税率全部丢失

系统导出的 488 条明细中：

- 销售税率非空：0 条；
- 采购税率非空：0 条。

但真实台账可由含税/不含税单价反推税率。当前数据库 489 条活动明细中，至少 461 条销售税率、385 条采购税率可以反推。

原因：

- 真实台账为旧 87 列结构，没有独立税率列；
- 导入器仅在新结构中读取税率，旧结构直接写入空值；
- 导入器没有使用“含税单价 ÷ 不含税单价 - 1”回填。

修改建议：

1. 旧格式导入时自动推导税率：

   ```text
   税率 = 含税单价 ÷ 不含税单价 - 1
   ```

2. 推导值应匹配允许税率集合，并设置容差；无法可靠判断时标记为待确认，不能静默写空。
3. 对当前数据库执行一次税率回填迁移，并生成无法推导清单。
4. 新模板导入时校验“税率、含税单价、不含税单价”三者一致。

### 5. 通用 `_ratio` 转换存在边界值错误

当前导出代码按“绝对值大于 1 就除以 100”转换所有比例字段。该规则无法区分税率和占比，存在以下错误：

- 税率 1% 存为 `1` 时会被导出为 100%；
- 税率 0.5% 存为 `0.5` 时会被导出为 50%；
- 毛利率 0.5% 若以百分点 `0.5` 保存，会被导出为 50%；
- 回款占比 100.03% 若以比例 `1.0003` 保存，会被除以 100，导出为约 1.00%。

修改建议：

1. 删除通用猜测式转换。
2. 税率字段统一保存为百分点 `0~100`，导出时固定除以 100。
3. 毛利率、回款占比统一保存为比例 `0~1`，导出时原值写入百分比格式。
4. 增加 0、0.5、1、3、6、9、13、100，以及 99.99%、100%、100.03% 的边界测试。

### 6. 3 条真实订单不是“导入漏行”，而是被系统操作删除

真实台账存在、系统导出缺少：

| 项目编号 | 订单号 | 销售订单金额 | 当前状态 |
|---|---|---:|---|
| AH24000193-01 | XSDD2026012100065 | 17,437.88 | 2026-07-21 测试数据清理时软删除 |
| AH24000149-01 | XSDD2026020900888 | 8,901.91 | 2026-07-14 删除测试时软删除 |
| AH24000193-01 | XSDD2026021000002 | 18,326.34 | 2026-07-21 测试数据清理时软删除 |

三条合计 44,666.13 元，正是系统销售订单总金额低于真实台账的主要原因。

其中两个 `AH24000193-01` 订单曾被把项目编号改为 `AH24000193-01test`，随后按“测试项目”清理，导致同项目下两条真实订单一起被删除。

修改建议：

1. 不要整库回滚；从清理前备份或真实台账中按明细恢复这 3 条记录。
2. 恢复前先保留 2026-07-21 之后系统新增的业务操作。
3. 测试数据清理不能只按字段中含 `test` 判断，应使用独立 `is_test_data` 标记和二次确认清单。
4. 清理前必须显示将受影响的项目、订单、货物和金额合计。

### 7. 100 元回款是系统新增数据，不是导出 Bug

系统操作日志显示，2026-07-21 15:34:49 给订单 `AH24000082-01 / XSDD2026021000233` 的明细新增了一笔 100 元回款；真实 Excel 没有这笔记录。

修改建议：

1. 确认该 100 元是测试数据还是真实回款。
2. 若为测试数据，按操作日志精确撤销该回款；若为真实数据，应同步回真实台账或以系统为新主数据源。
3. 回款占比应由系统自动计算，不能只记录金额而让占比为空。

### 8. 同一订单的订单日期不一致时被静默覆盖

订单 `XSDD2026010700242` 在真实台账中同时出现 2025-01-07 和 2025-01-08。系统按订单号合并后保留最后导入的日期，导致 18 条明细日期与原行不同。

修改建议：

1. 导入前校验同一“项目编号 + 订单号”的订单级字段必须一致。
2. 如订单号中含日期编码，应校验订单号日期与订单日期是否一致。
3. 冲突时整批拒绝并列出冲突行号，不能使用“最后一行覆盖”。

### 9. 多期导出只支持前两期，未满足上限 20 期

当前导出 SQL：

- 收票、入库、财务入账、开票只取第 1 期；
- 付款、回款只展开第 1、2 期；
- 合计字段会累计所有期，但第 3~20 期的日期、凭证号和单笔金额不会导出。

当前数据库尚未出现第 3 期数据，因此本次未触发金额差异；一旦录入第 3 期，导出明细将不完整。

修改建议：

1. 推荐增加“付款明细、回款明细、开票明细、收票明细”子工作表，每期一行，最多 20 期。
2. 主台账只保留各类合计，避免横向扩展到数百列。
3. 如必须严格保持宽表，则生成 1~20 期完整列组，并在第 21 期提交时拒绝。

## 五、P2：精度和源 Excel 质量

### 10. 分币级差异来自舍入顺序不同

共同订单中仅 3 个订单出现 0.01 元级的销售、交付、开票差异。真实 Excel 部分公式使用未舍入单价计算，系统按明细金额保留两位小数后再合计。

修改建议：

1. 明确统一规则：单价保留 6 位，单行金额按 `ROUND_HALF_UP` 保留 2 位，汇总使用已舍入的单行金额。
2. 导入时对比 Excel显示值与系统重算值，超过 0.01 元则报错。

### 11. 真实 Excel 自身存在公式和范围错误

真实工作簿实际只有 491 条业务明细，但使用区域扩展到 10815 行。

- 全表共出现 25,096 个公式错误值；
- 其中真实业务行有 380 个错误：
  - 一期回款占比除零 176 个；
  - 二期回款占比除零 176 个；
  - 毛利率除零 28 个；
- “交付数量”合计显示 0，实际合计 111,831；
- “待交付数量”合计显示 0，实际合计 184,261.2；
- 部分合计公式只统计到第 7 行，其他公式又扩展到第 7903、9857 行。

修改建议：

1. 比例公式增加分母判断或 `IFERROR`。
2. 将数据区转换为 Excel 表格并使用结构化引用，避免手写不一致的固定行号。
3. 清理第 496~10815 行的空白公式和格式，缩小使用区域。
4. 系统导入时不读取合计行，所有合计由数据库重新计算。

4. 修正数据库视图、导出 SQL、首页仪表盘和详情页公式。
5. 对旧数据回填销售税率和采购税率。
6. 从备份/真实台账精确恢复 3 条误删订单，并处理 100 元测试回款。
7. 增加 20 期、多订单同项目、零值/负值/极小比例、舍入边界等自动化测试。
8. 用本次 491 条真实明细做回归基准：金额合计容差 0.01 元，文本字段必须逐订单一致。
