# ERP 台账数据库字段字典与拓扑图

## 1. 说明

本文档以 `docs/erp_ledger_schema.sql` 和 `台账字段说明0716.xlsx` 为准，描述数据库中的实体表、字段用途、主外键关系和汇总视图。字段名称以 Excel B 列为最新口径，D 列作为调整说明，E 列本期不处理。

现有 docs/MySQL建表设计.md 包含早期设计草案，曾使用 project_order 等名称；当前实际 SQL 已拆分为 project 与 sales_order，不能混用。

### 通用约定

- 业务表通常使用 created_at、updated_at、deleted_at 记录生命周期；deleted_at IS NULL 表示有效记录。
- 金额主要使用 DECIMAL(18,2)，数量和单价使用 DECIMAL(20,6) 或 DECIMAL(18,6)。
- 多期发票、入库、付款、回款使用 phase_no；active_phase_no 根据 deleted_at 生成，用于保证有效期次唯一。
- *_date_text 保留原始 Excel 或业务文本；对应的 *_date 用于标准日期查询和排序。

## 2. 表总览

| 表 | 中文名称 | 作用 |
| --- | --- | --- |
| import_batch | 导入批次 | 记录 Excel 文件导入、解析、行数和批次状态 |
| ledger_raw_row | 台账原始行 | 保存每行原始 JSON、行号、哈希和解析结果 |
| erp_user | 系统用户 | 登录、角色、权限和部门范围 |
| operation_log | 操作日志 | 记录增删改、导入、备份等操作 |
| backup_record | 备份记录 | 记录备份文件及恢复所需信息 |
| project | 项目 | 项目、客户、部门和负责人主维度 |
| sales_order | 销售订单 | 订单头、日期、业务类型和状态 |
| order_line | 订单明细 | 货物、数量、单价、收入和订单金额 |
| purchase_info | 采购信息 | 采购厂商、采购税率、采购单价、采购金额和预留成本 |
| delivery_record | 交付记录 | 交付数量、交付金额和待交付金额 |
| purchase_contract | 采购合同 | 采购合同、付款条款和签约金额 |
| purchase_invoice | 采购收票 | 采购发票及多期收票金额 |
| warehouse_entry | 入库记录 | 入库日期、凭证和入库金额 |
| finance_invoice_check | 财务发票核验 | 财务收票核验和凭证信息 |
| finance_payment_entry | 财务入账付款 | 财务付款日期、凭证编码和入账金额 |
| purchase_payment | 采购付款 | 多期应付日期、付款日期和付款金额 |
| sales_contract | 销售合同 | 销售合同、签订日期和合同金额 |
| sales_invoice | 销售开票 | 发票、待开票和已交付未开票金额 |
| sales_receipt | 销售回款 | 多期回款、回款比例和通知单 |

| 上游 | 关系 | 下游 | 说明 |
| --- | --- | --- | --- |
| import_batch.id | 1:N | ledger_raw_row.import_batch_id | 一个批次有多条原始行 |

补充说明：

1. project.project_code 是业务唯一键；sales_order 使用 project_id 与 order_no 唯一约束。
2. `purchase_info.order_line_id` 有唯一键；`delivery_record` 由应用按有效 `order_line_id` 进行 upsert，两者业务上均按一对一使用。
3. 多期表的唯一约束覆盖 order_line_id 与 active_phase_no；软删除历史期次后，新记录不会复用旧期次。
4. import_batch.uploaded_by 当前没有数据库外键，是逻辑上的用户关联。
5. 视图还会使用 project_code、order_no 等业务字段进行筛选和聚合。

## 6. 汇总视图和计算口径

### v_order_line_finance

以项目、订单头、订单明细为主，聚合采购、合同、发票、付款和回款：

| 字段 | 计算或来源 |
| --- | --- |
| sales_tax_amount | order_value - revenue_no_tax |
| order_value | order_line.order_value |
| purchase_tax_amount | purchase_amount - cost_no_tax |
| purchase_amount | purchase_info.purchase_amount |
| labor_cost | purchase_info.labor_cost，预留，不参与利润公式 |
| other_cost | purchase_info.other_cost，预留，不参与利润公式 |
| sales_invoice_amount | 有效 sales_invoice.invoice_amount 求和 |
| total_finance_checked | 有效 finance_invoice_check.received_invoice_amount 求和 |
| total_finance_paid | 有效 finance_payment_entry.booked_amount 求和 |
| financial_accounts_payable | purchase_amount - total_finance_paid |
| total_received | 有效 sales_receipt.receipt_amount 求和 |
| total_paid | 有效 purchase_payment.payment_amount 求和 |
| accounts_receivable | order_value - total_received |
| accounts_payable | purchase_amount - total_paid |
| gross_profit_no_tax | revenue_no_tax - cost_no_tax |
| gross_profit_margin_no_tax | gross_profit_no_tax / revenue_no_tax * 100；收入为 0 时取 0 |
| gross_profit | order_value - purchase_amount |

### v_project_ledger_summary

按 project_code 聚合明细财务视图，得到项目级订单金额、采购金额、回款、应收、两套应付口径、毛利、人工成本和其他成本。

computed_close_status 规则：

- accounts_receivable 合计等于 0：closed
- accounts_receivable 合计不等于 0：open

### v_order_ledger_summary

按项目、订单号、订单日期、业务类型和统计类别聚合，输出订单级明细数、订单金额、采购金额、回款、应收、两套应付口径、毛利、人工成本和其他成本。

## 7. 一条业务数据的生命周期

1. Excel 文件创建一个 import_batch。
2. Excel 每行保存到 ledger_raw_row，保留原始 JSON、行号和哈希。
3. 解析成功后创建或更新 project 和 sales_order。
4. 每个商品明细写入 order_line，并关联原始行。
5. 订单明细补充采购、交付、合同、发票、入库、财务付款、采购付款和回款记录。
6. 三个财务视图实时计算应收、应付、毛利和关闭状态。
7. 用户操作写入 operation_log，备份动作写入 backup_record。
8. 业务删除使用 deleted_at 软删除，历史记录保留但不进入有效聚合。
