# Bug 修复记录 — 2026-07-24

## Bug A: 多期付款 due_payment_date 丢失

**文件**: `backend/app/routers/purchases.py:664-665`

**问题**: `add_purchase_payment` 中第 2 期及之后的付款强制将 `due_payment_date` 置为 `None`，即使用户传入了到期付款日也会丢失。

**根因**: 代码中存在 `if phase_no > 1: data["due_payment_date"] = None`，设计意图是一期付款才有到期日，但实际业务中多期付款都可能需要追踪到期日。

**修复**: 移除该强制置 None 逻辑，保留用户传入的 `due_payment_date` 值。

**影响范围**: `POST /api/purchases/{id}/payments` — 第 2-20 期付款创建

**验证方法**:
```
# 创建 3 期付款，每期都传 due_payment_date
POST /api/purchases/486/payments {"payment_date":"2026-08-01","due_payment_date":"2026-07-15","payment_amount":3000}
POST /api/purchases/486/payments {"payment_date":"2026-08-15","due_payment_date":"2026-08-01","payment_amount":3000}
POST /api/purchases/486/payments {"payment_date":"2026-09-01","due_payment_date":"2026-08-20","payment_amount":2456.81}
# 验证: GET /api/purchases/486 → payments[].due_payment_date 均保留
```

## Bug B: 采购侧 _next_phase 未过滤软删除记录

**文件**: `backend/app/routers/purchases.py:815-821`（第 1 轮修复）、`backend/app/routers/sales.py:574-576`（第 2 轮修复）

**问题**: `_next_phase` 查询 `MAX(phase_no)` 时未加 `AND deleted_at IS NULL`，导致软删除某期记录后再新建时，phase_no 跳过已删除的编号（如从 4 开始而非 1）。采购侧和销售侧各有一个独立 `_next_phase`，两处均存在相同缺陷。

**根因**: 两处 `_next_phase` 的 SQL 均缺少 `deleted_at IS NULL` 条件。首次修复遗漏了 `sales.py`。

**修复**:
1. 第 1 轮：在 `purchases.py` 的 `_next_phase` SQL 中补上 `AND deleted_at IS NULL`。
2. 第 2 轮：在 `sales.py` 的 `_next_phase` SQL 中补上 `AND deleted_at IS NULL`。

**影响范围**: 全部 7 张多期表：
- 采购侧（5 张）：`purchase_payment`、`purchase_invoice`、`warehouse_entry`、`finance_invoice_check`、`finance_payment_entry`
- 销售侧（2 张）：`sales_invoice`、`sales_receipt`

**验证方法**:
```
# sales.py 验证
# 创建 3 期销售开票 → 全部删除 → 再新建第 1 期
POST /api/sales/486/invoices → phase_no=1
POST /api/sales/486/invoices → phase_no=2
POST /api/sales/486/invoices → phase_no=3
# 删除全部 3 期
DELETE /api/sales/invoices/1
DELETE /api/sales/invoices/2
DELETE /api/sales/invoices/3
# 重建
POST /api/sales/486/invoices → phase_no=1 (修复前为 4)
```

## Bug C: 全额回款后不自动更新 close_status

**文件**: `backend/app/routers/sales.py:622-647`

**问题**: 回款累计达到 `order_value`（应收账款归零）后，`sales_order.close_status` 不会自动更新为「关闭」，仅 Dashboard 查询时通过 `CASE WHEN` 读时判断。

**根因**: 回款的增删改操作均未触发 `close_status` 的同步更新。

**修复**:
1. 新增 `_sync_close_status(conn, order_line_id)` 函数，检查该 order_line 所属 sales_order 的所有订单行是否 `accounts_receivable <= 0`，若是则设 `close_status = '关闭'`，若否则清除已有关闭状态。
2. 在 `add_sales_receipt`、`update_sales_receipt`、`delete_sales_receipt` 三个路由中调用该函数。

**影响范围**: `POST/PUT/DELETE /api/sales/{id}/receipts`

**验证方法**:
```
# 创建全额回款
POST /api/sales/486/receipts {"receipt_amount": 8901.91, "receipt_date": "2026-07-24"}
# 验证: GET /api/sales/486 → close_status = "关闭", accounts_receivable = 0.00
# 删除回款
DELETE /api/sales/receipts/{id}
# 验证: GET /api/sales/486 → close_status = null
```

## Bug D: 财务入账付款缺少累计金额上限校验

**文件**: `backend/app/routers/purchases.py:595-618, 620-644, 858-878`

**问题**: `add_finance_payment` 和 `update_finance_payment` 没有调用任何累计金额校验，用户可录入超过 `purchase_amount` 的财务付款金额，导致 `financial_accounts_payable` 为负数。

**根因**: 与采购付款 `_validate_payment_total` 不同，财务付款路由缺少对应的校验函数。

**修复**:
1. 新增 `_validate_finance_payment_total(conn, order_line_id, booked_amount, payment_id)` 函数，使用 `FOR UPDATE` 锁防并发，校验 `SUM(booked_amount) + new_booked_amount <= purchase_amount`。
2. 在 `add_finance_payment` 和 `update_finance_payment` 中调用该函数。

**影响范围**: `POST/PUT /api/purchases/{id}/finance-payments`

**验证方法**:
```
# 超额创建 → 应返回 422
POST /api/purchases/486/finance-payments {"booked_amount": 10000}
# → 422: "累计财务入账付款金额不能超过含税采购金额"

# 正常创建
POST /api/purchases/486/finance-payments {"booked_amount": 5000}
# → 200

# 累加超额 → 应返回 422
POST /api/purchases/486/finance-payments {"booked_amount": 4000}
# → 422 (5000+4000=9000 > 8456.81)
```

## Bug E: 财务发票校验缺少累计金额上限校验

**文件**: `backend/app/routers/purchases.py:535-559, 562-592, 880-901`

**问题**: `add_finance_invoice_check` 和 `update_finance_invoice_check` 没有累计金额校验，可录入超过 `purchase_amount` 的发票校验金额。

**修复**:
1. 新增 `_validate_finance_invoice_check_total(conn, order_line_id, received_invoice_amount, check_id)` 函数，校验 `SUM(received_invoice_amount) + new_amount <= purchase_amount`。`received_invoice_amount` 为 `None` 时跳过校验。
2. 在 `add_finance_invoice_check` 和 `update_finance_invoice_check` 中调用该函数。

**影响范围**: `POST/PUT /api/purchases/{id}/finance-invoice-checks`

**验证方法**:
```
# 超额创建 → 应返回 422
POST /api/purchases/486/finance-invoice-checks {"received_invoice_amount": 10000}
# → 422: "累计发票校验金额不能超过含税采购金额"
```
