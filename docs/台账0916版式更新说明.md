# 台账 0916 版式更新说明

本次以用户提供的《市场部业务台账模板0916.xlsx》作为版式、字段名与两种应收款公式的依据。参考文件只读解析，示例业务行未导入数据库。实现衔接工作区原有未提交修改，未发布生产。

## 数据口径与结构

- 交付应收款 = 当前有效交付收入 − 全部有效期次回款合计。
- 开票应收款 = 全部有效期次销售发票金额合计 − 全部有效期次回款合计。
- 两者是不同口径的余额，不能相加作为应收总额。没有交付或开票时基数为零，预收款产生的负余额保留，不截断为零。
- SQL 使用原有 DECIMAL 金额计算；开票和回款先按明细分别汇总再关联，避免多期记录产生乘积重复计数。软删除的记录不参与汇总。
- 两个新字段在 `v_order_line_finance` 计算，项目和订单汇总视图分别求和。无需新增业务表或重复存储余额，也无需拆分、覆盖历史金额。
- 原 `accounts_receivable` 保留“销售订单金额 − 回款”的兼容语义，页面、批量编辑与新版 Excel 的两种应收展示均切换到新字段。旧字段不改名、不删除。
- 关闭状态仍沿用系统现有规则。本次没有照搬参考文件中“小于 1”的关闭公式，也未改变利润、税金和金额单位等其他业务规则，防止版式更新带来额外财务口径变更。

## 前后端与导入安全

销售列表、销售详情、台账列表及详情、订单展开汇总、仪表盘和批量编辑同步展示新字段。批量编辑 CJ/CK 为只读；CM/CN 仍可维护费用。输入变化时预览会保留未显示的后续期开票与回款，保存以服务端结果为准。

标准追加导入与历史预检识别完整 91/92 列表头，按已确认版本映射费用列；维护导入保留 87/96 列历史布局支持，再统一规范为 92 列。空白尾列不会改变布局判断。未知、错位表头在写入前拒绝。

原始上传文件摘要、原始行和预检来源继续留存。Excel 中的应收款缓存值不作为业务输入，服务端按有效来源记录重算；批量接口拒绝提交两种应收字段。导入错误整批回滚，既有编辑冲突、部门权限、软删除和备份机制继续生效。

## 发布与回退

本次余额结构变化只扩展三个视图，现有业务表无需金额迁移。应用初始化会重建视图，应在现有发布维护流程内先备份、再配套发布后端和前端并刷新页面，避免新客户端访问旧版接口。视图 DDL 不依赖事务回滚；升级失败应恢复旧版本视图定义并核对后再开放访问，不需要删除业务数据。

隔离测试验证了从旧版视图升级、新版定义重复执行后业务表逐行保持一致。生产库未在本轮执行升级，也未重启业务服务。
