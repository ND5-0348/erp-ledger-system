## 问题核查与修改

1. Excel 已有完整模板及网页导入入口，无须运维手工写 SQL。导入前自动业务备份、追加导入（reset=False）、失败整批回滚原已存在。
2. 明细判重键为「项目编号＋订单号＋项目名称＋物资/服务名称＋规格型号＋数量＋单价＋采购厂商」；文本列 TRIM 后比较，空值与 0 视为相同。**不同项目名称、不同数量、不同单价或不同采购厂商都视为不同明细，可以共存**；只有上述字段完全一致的才判为重复。适用于 Excel 导入、单条新增、批量新增、单条修改和批量修改。
   - 本条在 2026-09-14 经用户确认修订。上一版规则是「项目编号＋订单号＋项目名称＋物资/服务名称＋规格」，其后果是把同一订单下同货物分批次、不同单价或不同供应商的合法明细误判为重复（实测 492 行样本中有 96 行被误拦），并禁止用改单价解除重复。现规则取消了该限制。
3. 台账底部汇总改为全部筛选结果（非当前分页）。金额明确为元，项目数为个；“未关闭”不再被误认成已关闭。已完工卡片沿用系统已关闭状态口径，数据库目前按应收余额判定项目关闭，并非独立工程竣工验收状态。
4. 仪表盘原已支持部门和订单日期联动，但前端只读取前500条。现在逐页加载完整权限范围内的项目、订单、采购和销售数据，再筛选统计；后端分页补充明细ID排序，避免同日期记录顺序不稳定。订单数按项目编号和订单号去重；所有明细均关闭才计入已关闭订单。金额显示元/万元，数量显示个。
5. 用户返回服务器证据：db_now=2026-09-14 14:33:18、utc_now=06:33:18，会话和全局时区均为+08:00。原接口返回无时区DATETIME，前端按UTC解释后额外加8小时。修复改为保持数据库会话+08:00，接口为无时区数据库时间附加+08:00；前端现有转换可正确显示14:33:18。不将新写入改成UTC，不改写历史数据。该证据确认当前数据库口径，不能证明更早导入的每条记录均使用相同口径。

延期预警原先按欠款超过50万元判断，且无结果时固定显示3，不能代表延期。按用户确认，现阶段显示“—（占位）”，并注明“待增加项目关闭时间后启用”。正式上线后增加项目关闭时间，再据此确定延期规则；本轮不添加该字段或计算预警数量。

## 2026-09-14 补充：网页导入报「第 N 行缺少项目编号或订单号」的处理

现象：在「订单管理 → 导入Excel」上传已按模板填好的文件，弹窗提示「第 N 行缺少项目编号或订单号」，N 正好是最后一条数据的下一行（492 条数据的文件报第 495 行，19 条数据的文件报第 22 行），整批回滚，一条也进不去。

根因（用真实文件在 MySQL 上复现确认）：生成式 AI 填充工具在表格末尾追加了一行 **AIGC 标识**，只有 A、B 两列有内容，分别是 `AIGC:<uuid>` 和 `{"Label":"1","ContentProducer":...,"ProduceID":...}`；该行字体为 `#E6E6E6`、9pt，在白色背景上肉眼几乎不可见。导入器把任何「有非空单元格」的行都当作业务行，于是这一行触发缺少编号的校验并中断整批导入。它既不是用户漏填，也不在用户视线范围内。

修改：

1. Excel 导入新增「非业务行」判定：一行若没有订单号、且在业务载荷列（部门、订单日期、项目名称、货物名称、规格型号、数量、单价、订单价值、采购厂商）上全为空，则跳过并计入 `skipped_rows`；导入结果和操作日志会记录跳过行数，前端成功提示也会显示。若一行缺项目编号或订单号**但填了业务字段**，仍按漏填报错整批回滚，不静默丢弃。
2. 判重键按上一节第 2 条修订，补入「数量＋单价＋采购厂商」。
3. 明细判重校验移到数量/单价解析之后执行（原来在解析之前，无法拿到这两个值）。

实测（独立验证库，未改动 `erp_ledger`）：

| 文件 | 结果 |
| --- | --- |
| `2026市场部业务台账_已填充 - 副本.xlsx`（19 条） | 成功 19，失败 0，跳过非业务行 1 |
| `2026市场部业务台账_已填充.xlsx`（492 条） | 成功 487，失败 4，跳过非业务行 1 |

剩余 4 行失败的原因是**文件本身就是重复数据**，不是代码问题，需要用户在文件里处理：

- 第 277、280、485 行：与同订单的另一行 91 列完全一致，是真正的重复明细，删除即可。
- 第 334 行：与同订单另一行仅「发票号／回款／是否关闭」不同（同一销售明细被录了两次，一行未回款、一行已回款关闭）。要么删除，要么与另一行合并保留一条。

因为导入策略仍是「有任何失败行就整批回滚」，上面这 4 行不清理的话，网页导入仍然会整批失败。

## 运维如何准备和导入 Excel

1. 在待导入环境的「台账管理」下载模板，将整理好的数据按表头映射到模板。第一张工作表、第二行91列表头、第三行起数据；不要删列、换顺序或改表头，不要直接上传任意格式原始表。
2. 替换/删除整行示例，不能只替换项目编号保留其余示例值。编号列预设为文本，保留前导零；业务日期使用有效日期。公式列在 Excel 中重新计算并保存，或粘贴为值，避免读取不到公式缓存。用 AI 工具填充过的文件，末尾可能多出一行浅色的 AIGC 标识（只占前两列、看不见内容），导入会自动跳过并在成功提示里告知跳过行数，不需要手工删除。
3. 同一订单不同项目名称填在每条明细“项目名称”列，不合并单元格。项目编号、订单号等关联字段每行填全。同一项目编号的部门、客户等项目级信息应保持一致。
4. 进入「订单管理 → 导入Excel」，选择 .xlsx（不超过20MB），等待成功或明确错误结果。失败时按提示行号修正后重试；不要在未确定前次请求结果时重复点击。
5. 导入是追加，不会自动替换现有测试数据。服务器交接记录为0条，但导入前必须核对当前环境；如需清理测试数据，另行制定备份和清理步骤，不调用默认 reset=True 的维护导入入口。
6. 完成后记录文件名、文件哈希、成功明细数、项目数、去重订单数和金额合计，导出结果复核。成功导入的同一文件再次上传应提示重复并回滚，不会覆盖已有数据。

约两万条数据尚未实测性能。首次先在测试库演练一份代表性样本，再按部门或完整项目分批，保留每批清单与合计，避免拆开同一项目。网页同步导入有300秒代理超时，生产大文件应先演练决定批次大小。若超时，先核查是否已写入再重试。系统自动业务备份不含全部账号与日志，正式初始导入前仍需运维完成全库备份。

- Excel 样本：同项目编号、同订单号，项目甲/项目乙各一行，同设备、同规格和相同单价，应成功；再分别测试两行规格均为空。重复同项目名称一行应整批回滚，原有记录不变。
- 台账底部“销售订单金额合计”：不筛选日期时合计筛选项目完整销售订单金额；筛选订单日期时只计范围内的订单明细金额；筛选开票日期时只计存在范围内开票记录的明细销售订单金额（不是开票金额），同一明细多次开票只计一次。两种日期同时填写时按同一明细取交集。所选范围包含起止当天。翻页不改变合计，空结果金额为0；项目数量仍按筛选项目及原项目状态统计。列表各项目行仍展示项目完整金额，底部日期筛选合计不能用完整项目行金额直接相加核验，应与对应明细核对。
- 仪表盘部门和日期组合筛选后，六项指标、趋势和排行同步。同订单多明细只计1个订单，金额仍按明细求和；至少使用501条以上样本验证分页完整性。
- 更新时间：修改一条测试数据并刷新；应显示北京时间。筛选无数据时显示 --；历史记录偏移须先核对原数据库时区，不能盲目修正。
