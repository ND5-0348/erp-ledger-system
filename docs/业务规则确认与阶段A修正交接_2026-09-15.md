# 业务规则确认与阶段 A 修正交接

日期：2026-09-15。本文记录用户在本会话逐项确认的最终业务规则，作为阶段 A 修正和阶段 B 设计的依据。此前将订单与子项目并列、将客户经理视为可变明细字段、将区域平台视为框架共享字段、排除采购厂商参与判重的说法均以本文纠正。

## 一、四级业务结构

**框架项目 → 订单 → 子项目 → 物资／服务明细**

1. 一个框架项目可以包含多个订单。
2. 一个订单属于一个框架项目，可以包含多个子项目。
3. 一个子项目属于具体订单，可以包含多条物资／服务明细。
4. Excel“项目编号”对应框架项目；Excel“订单号”对应订单；Excel“项目名称”对应子项目名称，不能当成整个框架项目唯一的名称。

```text
框架项目 P001
├─ 订单 O001
│  ├─ 子项目：园区网络建设
│  │  ├─ 路由器 / 型号A / 单价100 / 数量2 / 厂商甲
│  │  └─ 路由器 / 型号A / 单价100 / 数量2 / 厂商乙
│  └─ 子项目：办公楼网络建设
│     └─ 路由器 / 型号A / 单价100 / 数量2 / 厂商甲
└─ 订单 O002
   └─ 子项目：机房改造
      └─ 路由器 / 型号A / 单价100 / 数量2 / 厂商甲
```

上述四条明细均合法。订单、子项目、采购厂商不能被省略后再判断重复。

## 二、字段归属

| 所属层级 | 字段 | 一致性要求 |
| --- | --- | --- |
| 框架项目 | 客户经理、分公司、部门、三级团队 | 同一框架项目下全部订单、子项目和明细保持一致 |
| 订单 | 订单号以及现有订单级字段 | 订单与子项目是不同层级；本轮不凭样本改变其他订单字段规则 |
| 子项目 | 客户单位、最终用户、区域平台 | 同一订单的同一子项目内保持一致；不同子项目可不同，包括同订单下的不同子项目 |
| 明细 | 物资／服务名称、规格、销售单价、数量、采购厂商 | 按第三节组合判重 |

工作交接可整体调整框架项目的客户经理、分公司、部门、三级团队。这是显式的框架项目归属变更，不是普通追加导入自动覆盖共享信息。交接功能需有授权、原值核对、整体原子变更、操作日志，并纳入阶段 B 并发保护。具体交接界面的新增实现不因本记录自动扩展阶段 A 范围。

真实文件中同框架项目客户经理不同，可能涉及历史交接、混合口径或错误数据；必须列为待核实，不能根据样本放宽规则或自动挑选最后一行。用户尚未授权重写历史数据。

## 三、最终判重规则

限定在**同一框架项目、同一订单、同一子项目**内，以下五项组合唯一：

**物资／服务名称 ＋ 规格 ＋ 销售单价 ＋ 数量 ＋ 采购厂商**

- 五项全部相同：重复，应拒绝。
- 任一项不同：允许是不同明细，包括仅采购厂商不同。
- 跨子项目、跨订单、跨框架项目：允许五项完全相同。
- 空规格是允许值，不因空规格拒绝合法跨子项目记录。
- 采购厂商必须继续参与判重，不要撤回已有厂商维度。
- 文本空白、数值精度、空值归一化沿用经测试的规则；本轮未新授权改变“空数量与0”等历史语义。若发现语义风险，单独报告，不自行换口径。

目前Excel没有独立子项目编号。当前业务分组边界可表示为“框架项目编号＋订单号＋子项目名称”；不要只按子项目名称全库分组。子项目重命名、同订单同名但实际不同子项目等扩展情况，遇到时报告，不自行用客户单位或物资名称拼接新身份绕过冲突。

| 用例 | 预期结果 |
